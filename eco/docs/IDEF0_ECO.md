## 1. Контекстная диаграмма (A-0)

Единый функциональный блок **A0 — «Ведение экологической отчётности на КПО»** описывает модуль ECO в целом и его взаимодействие с внешней средой.

### Таблица 1 — Описание блока и дуг контекстной диаграммы

| Наименование | Вид | Описание |
|--------------|-----|----------|
| **Ведение экологической отчётности на КПО** | Основной процесс (A0) | Совокупность работ по аутентификации, контролю данных, журналу операций, учёту измерений и формированию отчётности в веб-модуле ECO |
| Данные партий отходов | Вход | Партии из модуля учёта (`/api/v1/accounting/batches`): объёмы, статусы, виды отходов |
| Данные операций движения | Вход | Операции накопления, переработки, вывоза и др. (`/api/v1/reporting/operations`) |
| Учётные данные пользователя | Вход | Email и пароль при входе в систему |
| Параметры запросов | Вход | Период, фильтры организации, формат экспорта, поля формы измерения |
| Законодательство РФ об отходах | Управление | ФЗ-89 «Об отходах производства и потребления» и подзаконные акты |
| ФККО и нормативы ПДК | Управление | Классификация отходов, предельно допустимые концентрации для контроля превышений |
| Ролевая модель доступа | Управление | Группы `eco_admin`, `eco_ecologist`, `eco_manager`; разграничение разделов UI |
| Политика работы с API | Управление | Флаг `USE_REMOTE_API`: чтение с платформы, ограничение записи справочников и операций |
| Отчёты (PDF / XML) | Выход | Файлы экспорта журнала операций (процесс P-14) |
| Дашборды и KPI | Выход | Сводные показатели, графики, списки превышений (P-19, P-20) |
| Результаты контроля согласованности | Выход | Статусы ok / warning / problem по организациям и партиям (P-08) |
| Записи экологических измерений | Выход | Данные измерений, зафиксированные экологом (P-17) |
| Администратор | Механизм | Реестр организаций, контроль данных, справочники |
| Эколог | Механизм | Журнал операций, измерения, экспорт, дашборд |
| Руководитель | Механизм | Просмотр дашбордов и KPI |
| Веб-модуль ECO (Django) | Механизм | Клиент отчётности: UI, агрегация, экспорт, правила целостности |
| API платформы (FastAPI + PostgreSQL) | Механизм | Единое хранилище `waste_complex`, REST `/api/v1/*` |
| Модули учёта, планирования, мониторинга | Механизм | Внешние источники первичных данных комплекса |

## 2. Диаграмма декомпозиции A0 (уровень 1)

Блок A0 разбит на **пять** подфункций (допустимый диапазон IDEF0: 3–6). Порядок доминирования (цифра в углу блока): от планирующей/контролирующей функции к вспомогательным.

| Код | Наименование | Доминирование |
|-----|--------------|---------------|
| A1 | Аутентификация и разграничение доступа | 1 |
| A2 | Администрирование и контроль качества данных | 2 |
| A3 | Ведение журнала операций и экспорт отчётов | 3 |
| A4 | Учёт экологических измерений | 4 |
| A5 | Формирование аналитики и KPI | 5 |

### Таблица 2 — Описание блоков и дуг декомпозиции первого уровня

| Наименование | Вид | Описание |
|--------------|-----|----------|
| **Аутентификация и разграничение доступа** (A1) | Процесс | P-01, P-02, P-03, P-21: вход через API, JWT в сессии, маршрутизация по роли |
| **Администрирование и контроль качества данных** (A2) | Процесс | P-04, P-06–P-10, P-11, P-12: организации, партии, справочник ФККО, панель data-control |
| **Ведение журнала операций и экспорт отчётов** (A3) | Процесс | P-13, P-14, P-15: просмотр движений, выгрузка pdf/xml |
| **Учёт экологических измерений** (A4) | Процесс | P-16–P-18: список измерений, создание записи (единственная штатная запись эколога) |
| **Формирование аналитики и KPI** (A5) | Процесс | P-19, P-20: дашборд KPI, отчётный дашборд по API reporting |
| Учётные данные пользователя | Вход (на A1) | Наследуется с контекста |
| Данные партий / операций | Вход (на A2–A5) | Наследуется с контекста; поступают через API после аутентификации |
| Параметры запросов | Вход (на A3–A5) | Фильтры, период, поля экспорта и формы |
| Ролевая модель доступа | Управление (на все блоки) | Наследуется с контекста |
| Законодательство, ФККО, политика API | Управление | Наследуется с контекста |
| Сессия и токен доступа | Выход A1 → вход A2–A5 | Результат успешной аутентификации |
| Сводка целостности данных | Выход A2 | Отчёт P-08 для администратора |
| Файлы отчётов | Выход A3 | Наследуется: PDF / XML |
| Записи измерений | Выход A4 | Наследуется с контекста |
| Дашборды KPI | Выход A5 | Наследуется с контекста |
| Веб-модуль ECO, API платформы | Механизм | Наследуется с контекста; на A1 — также пользователи всех ролей |

Описание объектов контекстной диаграммы, не повторённых выше, — в таблице 1.

## 3. Текст для раздела диплома (шаблон)

> Для описания существующих бизнес-процессов модуля отчётности построена функциональная модель IDEF0 в нотации «как есть». На контекстной диаграмме (рис. X) процесс **«Ведение экологической отчётности на КПО»** представлен единым блоком A0 с дугами взаимодействия с пользователями, платформой API и смежными модулями комплекса. Декомпозиция первого уровня (рис. Y) выделяет пять функций: аутентификацию, администрирование и контроль данных, журнал операций с экспортом, учёт измерений и формирование аналитики. Ограничение записи при `USE_REMOTE_API=true` отражено в управляющей дуге «Политика работы с API»; основные результаты для заказчика — регламентированные отчёты, KPI и подтверждение согласованности данных между модулями.
