# Информационное обеспечение программного комплекса

## Где что лежит

| Уровень | Что это | Где в проекте |
|---------|---------|----------------|
| **Концептуальная модель** | Сущности и связи без типов СУБД | `docs/diagrams/er_conceptual_simple.puml` → PNG |
| **Логическая ER-модель** | Атрибуты, PK/FK, связи 1:N, две СУБД | `docs/diagrams/er_logical.puml` → PNG |
| **Логическая модель (код)** | Те же сущности в приложении | Django-модели в `apps/*/models.py` + API-записи в `apps/integrations/records.py` |
| **Архитектура (пакеты UML)** | Слои и зависимости веб-модуля | `docs/diagrams/package-eco-webapp.puml`, `docs/UML_PACKAGE_ECO.md` |
| **Физическая модель** | Таблицы PostgreSQL на сервере | БД `waste_complex`, сервер API `http://178.57.217.79:8080` |
| **Локально (модуль отчётности)** | Только сессии | SQLite `db.sqlite3` (User, Session — не учётные данные) |

## Физическое размещение

- **СУБД:** PostgreSQL, база `waste_complex`
- **Доступ:** REST API (`/api/v1/core`, `accounting`, `planning`, `monitoring`, `reporting`, `auth`)
- Модули группы **не дублируют** учётные таблицы у себя — пишут/читают через API

## Основные таблицы (физическая модель)

### core_organization

| Поле | Тип | Описание |
|------|-----|----------|
| id | SERIAL PK | Идентификатор |
| name | VARCHAR | Название организации |
| address | VARCHAR | Адрес |
| email | VARCHAR | Email |
| phone | VARCHAR | Телефон |

### core_waste_type

| Поле | Тип | Описание |
|------|-----|----------|
| id | SERIAL PK | Идентификатор |
| code | VARCHAR | Код вида отхода |
| name | VARCHAR | Наименование |
| hazard_class | SMALLINT | Класс опасности (1–5) |
| fkko_code | VARCHAR | Код ФККО |
| description | TEXT | Описание |

### accounting_batch

| Поле | Тип | Описание |
|------|-----|----------|
| id | SERIAL PK | Идентификатор партии |
| organization_id | INT FK → core_organization | Организация |
| waste_type_id | INT FK → core_waste_type | Вид отхода |
| code | VARCHAR | Код партии |
| volume_tons | NUMERIC | Объём, т |
| status | VARCHAR | Статус (new, planned, in_process, …) |
| received_at | TIMESTAMP | Дата поступления |

### reporting_operation (журнал операций)

| Поле | Тип | Описание |
|------|-----|----------|
| id | SERIAL PK | Идентификатор |
| organization_id | INT FK | Организация |
| waste_type_id | INT FK | Вид отхода |
| operation_type | VARCHAR | receipt, recycling, removal, … |
| volume | NUMERIC | Объём, т |
| operation_date | DATE | Дата операции |
| notes | TEXT | Примечание |

### reporting_measurement

| Поле | Тип | Описание |
|------|-----|----------|
| id | SERIAL PK | Идентификатор |
| organization_id | INT FK | Организация |
| indicator_type | VARCHAR | air, wastewater, soil, noise |
| value | NUMERIC | Фактическое значение |
| norm | NUMERIC | Норматив (ПДК) |
| measurement_date | DATE | Дата измерения |

### auth_user (ядро)

| Поле | Тип | Описание |
|------|-----|----------|
| id | SERIAL PK | Идентификатор |
| email | VARCHAR UNIQUE | Логин |
| password_hash | VARCHAR | Пароль |
| role | VARCHAR | admin, ecologist, manager |

Таблицы модулей **планирования** и **мониторинга** (plan, process_stage и др.) хранятся в той же БД; к ним обращаются модули одногруппников через `/api/v1/planning` и `/api/v1/monitoring`.

## Логическая модель (фрагмент для диплома)

Соответствие Django-моделей (учебное описание структуры):

- `Organization` — организация
- `WasteType` — вид отхода  
- `Movement` — операция движения отходов (FK: organization, waste_type)
- `Measurement` — экологическое измерение (FK: organization)

Связи: Organization 1—* Movement, Organization 1—* Measurement, WasteType 1—* Movement.
