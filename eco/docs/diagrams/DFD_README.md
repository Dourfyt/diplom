**Важно:** сайта «вставил код — получил идеальную DFD Гейна–Сарсона» почти нет (в отличие от BPMN/Mermaid). Обычно: **шаблон + перенос блоков из таблицы** (логика у вас уже в `DFD_VALIDATION.md` и в файле `.drawio`).

### Как сделать draw.io аккуратнее за 10 минут

1. Откройте с библиотекой DFD:  
   [https://app.diagrams.net/?libs=dfd](https://app.diagrams.net/?libs=dfd)
2. **Arrange → Insert → Template → Software → Data flow 1** — возьмите оформление оттуда.
3. Откройте наш `dfd-eco.drawio` во второй вкладке и **перенесите связи** на чистый шаблон (или подвиньте блоки: **Arrange → Layout → Horizontal Flow**).
4. Включите сетку: **View → Grid**; выровняйте процессы в один ряд.
5. Экспорт: **File → Export as → PNG** (300 DPI для Word).

## Открыть готовый файл

1. [https://app.diagrams.net/](https://app.diagrams.net/?libs=dfd)
2. **File → Open** → `dfd-eco.drawio`
3. **File → Export as → PNG/SVG**

```bash
python3 scripts/generate_dfd_svg.py      # готовые SVG для Word
python3 scripts/generate_dfd_drawio.py   # draw.io для правок
```

## Элементы уровня 1

**Внешние сущности:** 1 Пользователь, 2 API-платформа.

**Процессы:** 1.0 Аутентифицировать пользователя; 2.0 Сформировать дашборд и журнал; 3.0 Сформировать файл экспорта; 4.0 Проверить согласованность данных; 5.0 Зарегистрировать измерение.

**Хранилище:** D1 Сессия (JWT, роль) — единственное хранилище в границах ECO.

Данные платформы (операции, измерения, организации) **не** показаны отдельными хранилищами на диаграмме ECO — они приходят через API (требование корректной DFD).

## Текст для §2.2

**DFD (Data Flow Diagram)** описывает движение данных между внешними сущностями, процессами обработки и хранилищами. Для модуля ECO построены контекстная диаграмма (уровень 0) и диаграмма уровня 1 в нотации Гейна–Сарсона.

**DFD уровня 0 (контекст системы) представлена на рисунке X.**  
**DFD уровня 1 веб-модуля представлена на рисунке Y.**

*Рисунок Y – DFD уровня 1 веб-модуля отчётности и экологического контроля.*

Подробности проверки: `DFD_VALIDATION.md`.
