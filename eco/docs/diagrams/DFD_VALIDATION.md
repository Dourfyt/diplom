# Проверка DFD модуля ECO по типичным ошибкам

## Что исправлено (было → стало)

| Проблема | Было | Стало |
|----------|------|-------|
| Внешние БД как «внутренние» хранилища | D2–D4 (операции, измерения, организации на API) | Только **D1 Сессия** внутри ECO; данные платформы — через **сущность API** |
| Смешение уровней | Только уровень 1 без контекста | Добавлена **контекстная DFD** `dfd-eco-level0.drawio` (процесс **0**) |
| Нумерация процессов | П.1–П.4 | **1.0–5.0** (иерархия для детализации уровня 2) |
| Слишком крупный процесс | П.2 включал и журнал, и экспорт | Разделено: **2.0** дашборд/журнал, **3.0** экспорт |
| Имена процессов | «Аутентификация», «Регистрация» (существительные) | **Аутентифицировать**, **Зарегистрировать** (глаголы) |
| Потоки | Часть обобщённых | Конкретные: «файл pdf/xml», «панель проблем» |

## Контрольный список (текущая модель)

### Методология
- [x] Один уровень абстракции на каждой диаграмме (L0 и L1 отдельно)
- [x] L0 сбалансирована с L1 (все потоки L1 «входят» в процесс 0)
- [x] Нумерация 1.0, 2.0 … 5.0
- [x] API — внешняя сущность, не процесс

### Структура
- [x] У каждого процесса есть вход и выход
- [x] Нет потоков хранилище ↔ хранилище
- [x] Нет потоков сущность ↔ сущность
- [x] 5 процессов (в рекомендуемом диапазоне 5–7)

### Семантика
- [x] Подписи на всех потоках
- [x] Процессы — действия, не роли

## Допущения (для диплома, 1 абзац)

Модель DFD описывает логические потоки данных веб-модуля ECO. Физическое хранение операций, измерений и справочников выполняется в БД платформы и отображается через внешнюю сущность «API-платформа»; внутри ECO персистентно хранится только сессия пользователя (JWT и роль).
