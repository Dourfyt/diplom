# Алгоритм построения BPMN–диаграмм для диплома (ГОСТ / BPMN 2.0)

## 1. Нормативная основа

- **BPMN 2.0** (OMG) — единая нотация процессов.
- **ГОСТ Р 56471–2015** — графические символы бизнес–процессов (пулы, дорожки, события, задачи, шлюзы).
- **ГОСТ 7.32–2017** — оформление рисунка в тексте диплома (подпись «Рисунок X – …», ссылка в тексте).

## 2. Структура диаграммы (как в учебном примере)

| Уровень | Элемент | Правило |
|---------|---------|---------|
| 1 | **Пул (Pool)** | Один пул на одну диаграмму = один процесс роли |
| 2 | **Дорожки (Lanes)** | 2–3 дорожки внутри пула по исполнителям |
| 3 | **Поток** | Сверху вниз (или слева направо), **без обрывов** |
| 4 | **События** | Одно **стартовое** (○), одно или несколько **конечных** (◎) |
| 5 | **Задачи** | Прямоугольники со скруглением; имя = глагол + объект |
| 6 | **Шлюз XOR** | Ромб с × ; на стрелках подписи «да» / «нет» |
| 7 | **Сервисные задачи** | В дорожке «Система» / «API» (иконка шестерни в bpmn.io) |

Рекомендуемые дорожки для модуля ECO:

1. **Пользователь** (администратор / эколог / руководитель) — действия в браузере.  
2. **Веб–модуль ECO** — обработка на сервере Django (фильтры, агрегация, экспорт файла).  
3. **API платформы** — запросы к REST API и PostgreSQL.

## 3. Пошаговый алгоритм

### Шаг 1. Определить границы

- **Один бизнес-процесс = одна диаграмма** (2–4 ключевых процесса в дипломе достаточно).
- Выбрать сквозные процессы с ясным триггером и результатом (см. `БИЗНЕС_ПРОЦЕССЫ_ECO.md`: P-01, P-08, P-14, P-17).
- Не смешивать на одном рисунке «меню со всеми разделами роли» — это не BPMN-процесс, а карта функций.
- Не включать процессы других модулей комплекса (учёт партий на складе) — только **потребление данных** через API.

### Шаг 2. Составить таблицу шагов

| № | Исполнитель | Действие | Тип BPMN |
|---|-------------|----------|----------|
| 1 | Пользователь | … | User Task |
| 2 | ECO | … | Service Task |
| 3 | API | … | Service Task |

### Шаг 3. Разместить в дорожках

- Старт — в дорожке пользователя (верх).
- Цепочка: пользователь ↓ ECO ↓ API ↓ (при необходимости возврат вверх к следующему шагу).
- **Запрещено**: задачи без входящей и исходящей стрелки (кроме старта/конца).

### Шаг 4. Добавить шлюзы

- После входа: «Учётные данные верны?»
- В цикле меню: «Выбран раздел» / «Продолжить работу?»
- Перед экспортом: «Сформировать файл?»

### Шаг 5. Проверка связности (контрольный список)

- [ ] От старта до каждого конца есть непрерывный путь стрелок.
- [ ] У каждого шлюза XOR ровно 2+ исходящих потока с подписями.
- [ ] Нет «звезды» с 6 ветками без возврата к общему шлюзу (лучше цикл «меню → раздел → меню»).
- [ ] В XML у **каждого** `sequenceFlow` есть `BPMNEdge` с waypoints.
- [ ] Имена задач на русском, **без HTTP-методов и URL** в подписях (как в эталоне: «Сформировать список депозитов», а не `GET /deposits`).
- [ ] Дорожка **API платформы**: глаголы «Проверка…», «Формирование…», «Сохранение…»; дорожка **сайта (ECO)**: «Получение…», «Аутентификация…», «Анализ…».

### Шаг 6. Оформление в bpmn.io

1. https://demo.bpmn.io/ → Create diagram.  
2. Добавить **Participant** (пул) → разделить на **3 Lane**.  
3. Строить процесс сверху вниз.  
4. File → Open — только после проверки XML; либо рисовать вручную по алгоритму.  
5. Export SVG → Word, ширина 14–16 см.

### Шаг 7. Подпись в дипломе

> Рисунок 2.1 – BPMN–диаграмма бизнес–процессов администратора веб–модуля отчётности и экологического контроля

## 4. Типичные ошибки (как в старых файлах)

| Ошибка | Как исправить |
|--------|----------------|
| Блоки без стрелок | Добавить sequenceFlow и BPMNEdge |
| Два пула + messageFlow без координат | Один пул, три дорожки; API — нижняя дорожка |
| Шлюз «меню» с 6 исходящими в стороны | Цикл: шлюз → одна ветка → возврат к шлюзу |
| `</bpmndi:BPMNDiagram>` вместо `</bpmndi:BPMNPlane>` | Закрывать теги по схеме XML |
| Смешение collaboration и process DI | `bpmnElement` плоскости = id процесса |
