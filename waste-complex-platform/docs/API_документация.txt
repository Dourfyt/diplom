================================================================================
  1. ОБЩИЕ СВЕДЕНИЯ
================================================================================

1.1. Заголовки запросов
--------------------------------------------------------------------------------
  Content-Type: application/json     — для POST, PATCH с телом
  Accept: application/json           — рекомендуется

1.2. Аутентификация
--------------------------------------------------------------------------------
  Модуль /api/v1/auth — JWT (Bearer).
  После login/register используйте заголовок:
    Authorization: Bearer <access_token>
  Остальные модули в прототипе по-прежнему доступны без токена.

1.3. Коды ответов HTTP
--------------------------------------------------------------------------------
  200 OK              — успешный GET, PATCH, POST (без создания)
  201 Created         — успешное создание ресурса
  400 Bad Request     — ошибка валидации / бизнес-правило
  404 Not Found       — ресурс не найден
  422 Unprocessable   — ошибка схемы Pydantic (неверные поля)
  500 Internal Error  — ошибка сервера

1.4. Формат ошибки
--------------------------------------------------------------------------------
  FastAPI возвращает JSON с полем "detail":
  {"detail": "План не найден"}
  или массив ошибок валидации для 422.

1.5. Префиксы модулей
--------------------------------------------------------------------------------
  /api/v1/auth          — регистрация, вход, профиль
  /api/v1/core          — ядро, справочники, health
  /api/v1/accounting    — учёт поступления и классификации
  /api/v1/planning    — планирование (явный префикс)
  /api/v1             — планирование (совместимость, те же методы)
  /api/v1/monitoring  — мониторинг этапов
  /api/v1/reporting   — отчётность и экоконтроль

1.6. CORS
--------------------------------------------------------------------------------
  Разрешённые origins задаются переменной CORS_ORIGINS на сервере.
  При работе через nginx-прокси фронтенда CORS не требуется.

--------------------------------------------------------------------------------
POST /api/v1/auth/register
--------------------------------------------------------------------------------
  Описание:   Регистрация пользователя.
  Тело (UserRegister):

--------------------------------------------------------------------------------
GET /api/v1/auth/user
--------------------------------------------------------------------------------
  Описание:   Текущий пользователь по токену.
  Заголовок:  Authorization: Bearer <access_token>
  Ответ 200:  UserOut
  Ошибки: 401 — нет или невалидный токен

  4. МОДУЛЬ УЧЁТА — /api/v1/accounting
================================================================================
  Дипломный модуль: учёт поступления и классификации отходов.
  Создаёт партии в общей таблице waste_batches.

--------------------------------------------------------------------------------
GET /api/v1/accounting/batches
--------------------------------------------------------------------------------
  Описание:   Список всех партий (с приоритетом и риском хранения).
  Ответ 200:  BatchOut[]

--------------------------------------------------------------------------------
POST /api/v1/accounting/batches
--------------------------------------------------------------------------------
  Описание:   Регистрация новой партии.
  Тело запроса (BatchCreate):
  {
    "code": "P7",                    // обяз., 2–16 символов, unique
    "name": "Наименование отхода",
    "fkko_code": "4 12 110 01 11 4",
    "hazard_class": 4,               // 1–5
    "volume_tons": 10.5,             // > 0
    "storage_deadline_hours": 48,    // > 0
    "route_codes": "L1,L2",          // по умолчанию "L1,L2"
    "economic_value": 300,
    "organization_id": 1,            // опционально
    "waste_type_id": 1,              // опционально
    "source_department": "Цех №3",
    "classification_note": ""
  }
  Ответ 201:  BatchOut
  Побочные эффекты:
    - создаётся документ acceptance_act (АП-{code})
    - запись в waste_operations (receipt), если указан organization_id
    - создаются строки batch_stage_progress для мониторинга
    - генерируется qr_token для QR

  Ошибки:
    400 — партия с таким code уже существует

--------------------------------------------------------------------------------
PATCH /api/v1/accounting/batches/{batch_id}/classify
--------------------------------------------------------------------------------
  Описание:   Классификация партии (класс опасности, ФККО, маршрут).
  Параметры пути: batch_id — integer
  Тело (BatchClassify):
  {
    "hazard_class": 3,
    "fkko_code": "4 06 200 03 51 3",   // опционально
    "classification_note": "уточнено лабораторией",
    "route_codes": "L1"                 // опционально
  }
  Ответ 200:  BatchOut (status → "classified")

--------------------------------------------------------------------------------
GET /api/v1/accounting/batches/{batch_id}/documents
--------------------------------------------------------------------------------
  Описание:   Документы по партии (акты приёма и др.).
  Ответ 200:
  [
    {
      "id": 1,
      "doc_type": "acceptance_act",
      "doc_number": "АП-P7",
      "created_at": "2026-05-16T10:00:00"
    }
  ]

--------------------------------------------------------------------------------
GET /api/v1/accounting/batches/{batch_id}/balance
--------------------------------------------------------------------------------
  Описание:   Баланс партии: поступило / переработано / вывезено / остаток.
  Ответ 200:  BatchBalanceOut
  {
    "batch_id": 1,
    "batch_code": "P1",
    "received_tons": 12.0,
    "processed_tons": 8.0,
    "disposed_tons": 2.0,
    "remaining_tons": 2.0
  }
  Формула: remaining = received − processed − disposed

--------------------------------------------------------------------------------
GET /api/v1/accounting/operations
--------------------------------------------------------------------------------
  Описание:   Журнал операций (фильтры опциональны).
  Query:      batch_id, operation_type
  Ответ 200:  WasteOperationOut[]

--------------------------------------------------------------------------------
POST /api/v1/accounting/operations
--------------------------------------------------------------------------------
  Описание:   Запись факта переработки или вывоза (журнал движения отходов).
  Тело (OperationCreate):
  {
    "batch_id": 1,
    "operation_type": "processing",   // processing | disposal | export | transfer
    "quantity_tons": 5.0,
    "organization_id": 1,             // опционально, иначе из партии
    "notes": "Переработка на линии L2"
  }
  Ответ 201:  WasteOperationOut
  Побочные эффекты:
    - обновляется status партии: processing → при переработке;
      done → если остаток ≈ 0
  Ошибки:
    400 — превышен остаток партии

POST /api/v1/plans/build
POST /api/v1/planning/plans/build
--------------------------------------------------------------------------------
  Описание:   Построить новый черновик расписания (жадный планировщик).
  Тело (BuildPlanRequest):
  {
    "name": "Сменный план",       // по умолчанию
    "horizon_hours": 8,           // 1–168, по умолчанию 8
    "batch_ids": [1, 2, 3]        // опционально, иначе все accepted/queued
  }
  Ответ 200:  PlanActionResult
  {
    "plan": { ... PlanOut ... },
    "message": "Создан черновик версии N..."
  }

    - старые черновики (не симуляции) → archived
    - создаются schedule_items
    - проверка уведомлений T2 (риск хранения)

--------------------------------------------------------------------------------
POST /api/v1/plans/{plan_id}/approve
POST /api/v1/plans/{plan_id}/publish    (алиас, то же действие)
POST /api/v1/planning/plans/{plan_id}/approve
--------------------------------------------------------------------------------
  Описание:   Утвердить план → единственный рабочий производственный план.
  Тело:       не требуется
  Ответ 200:  PlanActionResult
  Побочные эффекты:
    - другие утверждённые планы → archived
    - approved_at = текущее время
    - синхронизация batch_stage_progress для мониторинга
  Ошибки:
    400 — нельзя утвердить симуляцию
    404 — план не найден

--------------------------------------------------------------------------------
POST /api/v1/plans/{plan_id}/replan
POST /api/v1/planning/plans/{plan_id}/replan
--------------------------------------------------------------------------------

  {
    "line_code": "L2",
    "duration_hours": 8,              // 0.5–72
    "reason": "Аварийная остановка"
  }
  Ответ 200:  PlanActionResult (новый черновик с parent_plan_id)

--------------------------------------------------------------------------------
POST /api/v1/simulations
POST /api/v1/planning/simulations
--------------------------------------------------------------------------------
  Описание:   Сценарное моделирование «что если».

--------------------------------------------------------------------------------
GET /api/v1/monitoring/batches
--------------------------------------------------------------------------------
  Описание:   Все партии со статусами по каждому этапу.
  Ответ 200:  MonitoringBatchOut[]
  {
    "batch": { ... BatchOut ... },
    "stages": [ ... StageProgressOut ... ]
  }

  StageProgressOut:
  {
    "id": 1,
    "batch_id": 2,
    "batch_code": "P2",
    "stage_id": 2,
    "stage_code": "ST-L1",
    "stage_name": "Сушка / сепарация",
    "status": "in_progress",
    "status_label": "В работе",
    "planned_start": "...",
    "planned_end": "...",
    "actual_start": "...",
    "actual_end": null,
    "deviation_percent": null
  }

  Статусы этапа: pending | in_progress | done | delayed

--------------------------------------------------------------------------------
GET /api/v1/monitoring/batches/{batch_id}
--------------------------------------------------------------------------------
  Описание:   Одна партия с этапами.
  Ответ 200:  MonitoringBatchOut

--------------------------------------------------------------------------------
GET /api/v1/monitoring/batches/qr/{token}
--------------------------------------------------------------------------------
  Описание:   Поиск партии по QR-токену (поле qr_token в waste_batches).
  Ответ 200:  MonitoringBatchOut
  Ошибки:   404 — не найдено

--------------------------------------------------------------------------------
GET /api/v1/monitoring/batches/{batch_id}/balance
--------------------------------------------------------------------------------
  Описание:   Баланс партии (тот же BatchBalanceOut, что в учёте).
  Ответ 200:  BatchBalanceOut

--------------------------------------------------------------------------------
PATCH /api/v1/monitoring/batches/{batch_id}/stages/{stage_id}
--------------------------------------------------------------------------------
  Описание:   Обновить статус этапа партии.
  Тело (StageStatusUpdate):
  {
    "status": "done",
    "quantity_tons": 7.5,          // опционально: факт переработки, т
    "record_processing": true      // при done — запись в журнал учёта (default true)
  }
  Ответ 200:  StageProgressOut
  Логика:
    in_progress → фиксируется actual_start
    done        → actual_end, deviation_percent;
                  если record_processing: операция processing в waste_operations
                  (quantity_tons или planned_output_tons из утверждённого плана)

--------------------------------------------------------------------------------
POST /api/v1/monitoring/batches/{batch_id}/stages/{stage_id}/events
--------------------------------------------------------------------------------
  Описание:   Зарегистрировать событие на этапе.
  Тело (StageEventCreate):
  {
    "event_type": "note",           // произвольный тип
    "comment": "Замечание оператора",
    "operator_name": "Иванов И.И."
  }
  Ответ 200:
  {
    "id": 1,
    "created_at": "2026-05-16T12:00:00"
  }

BatchOut
  id, code, name, fkko_code, hazard_class, volume_tons,
  storage_deadline_hours, received_at (ISO 8601), status,
  economic_value, route_codes, organization_id?, waste_type_id?,
  source_department, qr_token, priority_score?, storage_risk_hours?,
  processed_tons?, disposed_tons?, remaining_tons?

BatchBalanceOut
  batch_id, batch_code, received_tons, processed_tons, disposed_tons, remaining_tons

PlanStatus (enum в БД)
  draft, approved, archived, published (устаревший алиас approved)

NotificationStatus
  new, sent, acknowledged

# Health
curl http://178.57.217.79:8080/api/v1/core/health

# Список партий (планирование)

# Построить план
curl -X POST http://178.57.217.79:8080/api/v1/plans/build \
  -H "Content-Type: application/json" \
  -d '{"name":"Тестовый план","horizon_hours":8}'

# Утвердить план id=1
curl -X POST http://178.57.217.79:8080/api/v1/plans/1/approve

# Регистрация партии (учёт)
curl -X POST http://178.57.217.79:8080/api/v1/accounting/batches \
  -H "Content-Type: application/json" \
  -d '{
    "code":"P99",
    "name":"Тестовая партия",
    "fkko_code":"4 12 110 01 11 4",
    "hazard_class":4,
    "volume_tons":5,
    "storage_deadline_hours":24,
    "organization_id":1
  }'

# Мониторинг: все партии с этапами
curl http://178.57.217.79:8080/api/v1/monitoring/batches

# Отчётность: дашборд
curl http://178.57.217.79:8080/api/v1/reporting/dashboard

# Симуляция аварийного сценария
curl -X POST http://178.57.217.79:8080/api/v1/simulations \
  -H "Content-Type: application/json" \
